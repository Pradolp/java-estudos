Convenções de Nomenclatura em Java

Como nomear classes, métodos, variáveis, constantes, pacotes, genéricos e tudo mais. Seguir essas regras deixa o código legível para qualquer pessoa (inclusive você daqui a seis meses) e evita atrito com ferramentas, frameworks e revisores.

Regra de ouro: Java diferencia maiúsculas de minúsculas, então Product e product são coisas diferentes. A capitalização é a única forma rápida de olhar para um nome e saber se é classe ou variável.

2 Classes e interfaces

Toda palavra começa com maiúscula, sem underscores. Use substantivos, no singular.

NomePor quê
ProductcorretoSubstantivo, singular, UpperCamelCase
ProductsevitePlural só faz sentido se a classe representa uma coleção
producterradoMinúscula é convenção de variável
Product_ItemerradoUnderscore não se usa em nomes de classe
ClientePedidocorretoSem acentos nem cedilha — identificadores Java são ASCII por convenção

Interfaces

Mesma regra da classe. O nome ideal descreve uma capacidade ou um papel, não um “objeto”: adjetivos ou verbos terminados em -able, -ible, ou papéis do domínio. 

// capacidade → adjetivo
public interface Comparable<T> { }
public interface Runnable { }
public interface Serializable { }

// papel do domínio → substantivo
public interface PaymentGateway { }
public interface CustomerRepository { }
public interface EmailSender { }

// ❌ prefixo "I" e sufixo "Impl" são considerados ruído
public interface IProductService { }
public class ProductServiceImpl { }
Não use o prefixo I (IProductService). Isso é herança do C#/COM, não é convenção Java. Quem quiser saber que é interface usa a IDE ou o próprio interface na declaração.

Classes com sufixo de papel

Sufixos são úteis quando a classe cumpre um papel específico conhecido:

Criação

ProductFactory, ProductBuilder, InvoiceDto

Exceções

InvalidPriceException, StockUnavailableException

Eventos / Listeners

OrderPlacedEvent, ButtonClickListener

Testes

ProductTest, ProductIntegrationTest

3 Métodos

Começam com minúscula. Sempre. O nome deve dizer o que o método faz ou retorna.

// ✅ verbo + complemento, lowerCamelCase
public double calculateTotal()
public void   addProducts(int quantity)
public void   removeProducts(int quantity)
public Product findById(long id)

// ❌ PascalCase em método (nome de classe disfarçado)
public double TotalValueInStock()
public void   AddProducts(int quantity)

// ❌ prefixos/sufixos redundantes
public double getCalculateProductTotalValue()

Prefixos consagrados

PrefixoQuando usarExemplos
getGetter de propriedade (JavaBeans)getName(), getTotalPrice()
setSetter de propriedadesetName(String name)
is / has / canGetter boolean; a pergunta deve ser respondível com sim/nãoisActive(), hasStock(), canCancel()
toConverte para outro tipo (não muta o objeto)toString(), toBigDecimal(), toDto()
of / from / valueOfFábrica estática; of recebe o dado, from recebe outra representaçãoList.of(...), Duration.ofSeconds(5)
parseEntrada textual → objetoInteger.parseInt("42")

Métodos que sobrescrevem a classe Object

toString(), equals() e hashCode() são declarados em minúsculas na classe Object — então você não pode renomeá-los. Escrever ToString() cria um método novo e inútil, sem relação com o original. Sempre use @Override para pegar esse erro na compilação. 

@Override
public String toString() {
    return name + ", $ " + price + ", " + quantity + " units";
}
Nomeie pelo que o método faz, não por como ele faz. calculateTotal() é melhor que loopOverProductsAndSumPrices().

4 Variáveis, campos e parâmetros

Tudo em lowerCamelCase, sem prefixos, com nome que descreve o conteúdo.

NomeObservação
int quantitycorretoDiz o que a variável contém
int q, int qtdeviteAbreviação obscura; só loops e escopos minúsculos aceitam nomes curtos
int n1, int n2eviteNumeração em nome quase sempre indica código que devia ser lista/array
String productNameeviteRepetir o nome da classe no campo é redundante → name
String strName, int iCounterradoNotação húngara (tipo no nome) — a IDE já mostra o tipo
String _name, String m_nameerradoPrefixo “de C++/convenção antiga”; em Java campo privado não leva prefixo
double salarioerradoSem acentos — o compilador aceita, mas quebra encoding e é um inferno em diff/log

Variável final local

Continua lowerCamelCase — UPPER_SNAKE_CASE é reservado para constantes de classe (static final). 

final double taxRate = 0.18;   // ✅ local constant
static final double TAX_RATE = 0.18; // ✅ constante da classe

Nomes curtos aceitáveis

  • i, j, k — índices de laço for.
  • x, y — coordenadas matemáticas.
  • e — exceção capturada em bloco catch de escopo curto.

Evite l (parece 1) e O / I isolados. Se o laço passa de três linhas, dê um nome de verdade.

5 Constantes

static final → UPPER_SNAKE_CASE. O valor não muda durante a execução.

public class Order {
    public static final int   MAX_ITEMS        = 100;
    public static final int   DEFAULT_QUANTITY = 1;
    public static final String STATUS_PENDING  = "PENDING";
    private static final long  TIMEOUT_MILLIS  = 5_000L; // constante de implementação: private
}
Sobrenome, não sublinhado. Para sufixos de unidade prefira _MS, _SECONDS, _BYTES, _RATIO — quem lê o código sabe a unidade sem abrir a declaração.

Atenção: final sozinho não cria constante

final List<String> items = new ArrayList<>();
items.add("x");  // legal! o final trava a referência, não o conteúdo

// por isso `static final List` só é "constante" se for imutável:
public static final List<String> DEFAULT_TAGS = List.of("a", "b");

6 Pacotes e arquivos

// ✅ pacote: tudo minúsculo, ponto como separador, domínio invertido
package com.empresa.projeto.modulo;

// mais exemplos
com.empresa.vendas.pedido
com.empresa.vendas.pedido.modelo      // subpacote: divida por responsabilidade
br.com.minhaLoja.estoque              // evite maiúsculas e camelCase aqui
RegraDetalhe
Só minúsculascom.empresa.pedidos, nunca com.Empresa.Pedidos
Sem hífen, sem espaçoHífen é inválido em identificador Java
Nome do arquivo = classe públicaProduct.java precisa conter public class Product (case-sensitive)
Uma classe pública por arquivoClasses auxiliares podem ser package-private no mesmo arquivo
Palavras reservadas proibidasint, class, new, return, var… não podem ser usadas nem como nome de classe

7 Tipos genéricos (type parameters)

Uma letra maiúscula só. Se precisar de duas letras, use T1 — nunca Type1.

LetraSignificadoExemplo
TType (tipo genérico comum)class Box<T>
EElement (elemento de coleção)interface List<E>
K / VKey / Value (mapa)interface Map<K, V>
NNumberclass Stack<N extends Number>
RResult / Returninterface Function<T, R>
S, U, V2º, 3º, 4º tipo genéricoclass Trio<A, B, C>
 
// ✅
public class Cache<K, V> { }
public <T> List<T> filter(List<T> input) { }

// ❌
public class Cache<KeyType, ValueType> { }
public class Cache<key, value> { }   // parece variável, não tipo

8 Enums, records e anotações

Enum

Tipo em UpperCamelCase (singular), valores em UPPER_SNAKE_CASE.

public enum OrderStatus {   // singular: cada valor É um status
    PENDING_PAYMENT,
    PAID,
    SHIPPED,
    CANCELLED
}

correto DayOfWeek.MONDAY   evite OrderStatus.pendingPayment   evite OrderStatuses.PAID

Record (Java 16+)

O nome do record é uma classe normal; os componentes são campos lowerCamelCase.

public record Money(double amount, Currency currency) { }

// acessores gerados: amount() e currency() — sem prefixo "get" (é a convenção de record)
Money m = new Money(10.0, Currency.getInstance("BRL"));
m.amount();   // ✅
m.getAmount(); // não existe

Anotações

@Override
@Deprecated
@FunctionalInterface
@SuppressWarnings("unchecked")

Anotações customizadas seguem UpperCamelCase e costumam ser adjetivos: @Transactional, @Validated.

9 Boas práticas de nome

Booleanos: perguntas

Devem poder ser lidos como sim/não.

isActive
hasStock
canCancel
isEmpty()

Siglas: trate como palavra

Maiúscula só na primeira letra.

XmlParser
parseXml()
HttpClient
userId

Units e coleções

Plural para coleções, unidade no nome.

List<Product> products
long timeoutMillis
double weightKg

O tamanho acompanha o escopo

Escopo curto, nome curto; campo de classe, nome completo.

for (int i = 0; ...)      // ok
double invoiceTotalBaseAmount  // campo

Siglas: escolha uma e mantenha

As duas escolas convivem no ecossistema: Google Java Style trata a sigla como palavra (XmlHttpRequest), enquanto o estilo Oracle antigo a mantém em caixa alta (XMLHTTPRequest). A regra que importa é consistência dentro do projeto — o pior cenário é ter getUserId() e getURL() no mesmo arquivo.

Nomes de testes

class ProductTest {

    @Test
    void shouldReturnZeroWhenQuantityIsZero() { }

    @Test
    void shouldThrowWhenPriceIsNegative() { }
}

Padrões comuns: shouldXxxWhenYyy(), givenXxx_whenYyy_thenZzz(), metodo_estadoEsperado(). Qualquer um serve — desde que diga o comportamento esperado.

10 O que evitar

Caracteres $ e _

Use apenas letras e dígitos. O $ é usado por compiladores para classes internas (Outer$Inner); _ sozinho é erro de compilação no Java 9+.

String user_name;
int $value;
int _;  // não compila (Java 9+)

Nomes genéricos

data, info, obj, temp, manager, helper, util, process — não dizem nada e envelhecem mal.

Object data;
class DataManager2 {} // o "2" é a prova

Nomes que mentem

Se o método mudou de comportamento, renomeie. getUser() que grava no banco é uma armadilha.

// busca E atualiza??
User getUser(long id)

Números no nome

value1, value2, copy2 quase sempre pedem um array, uma classe ou um parâmetro.

double price1, price2;
List<Double> prices;
Dica visual: o compilador aceita praticamente qualquer identificador válido — inclusive int banana = 42;. Quem garante a qualidade é a revisão de código e você mesmo.

11 Antes e depois: aplicando no seu código

O exemplo abaixo é a classe Products deste repositório (src/introducaopoo/exercicio1) reescrita seguindo as convenções.

antes o que estava no arquivo depois com as convenções aplicadas 
// ======================= ANTES =======================
package introducaopoo.exercicio1;

public class Products {                    // plural
    public String productName;          // redundante + campo público
    public int    productQtd;           // abreviação de "quantity"
    public double productPrice;

    public double TotalValueInStock() {   // método em PascalCase
        return productPrice * productQtd;
    }

    public void AddProducts(int quantity) { }
    public void RemoveProducts(int quantity) { }

    public String ToString() {            // não sobrescreve nada!
        return productName + ", $ " + productPrice;
    }
}
// ======================= DEPOIS =======================
package introducaopoo.exercicio1;      // ✅ já estava correto: minúsculo

public class Product {                     // substantivo, singular, UpperCamelCase
    private String name;                 // campo: lowerCamelCase, sem prefixo
    private int    quantity;              // nome completo, sem abreviação
    private double price;                 // encapsulado (private)

    public double totalValueInStock() {    // método: lowerCamelCase
        return price * quantity;
    }

    public void addProducts(int quantity) {
        this.quantity += quantity;        // this desempata parâmetro x campo
    }

    public void removeProducts(int quantity) {
        this.quantity -= quantity;
    }

    @Override                            // garante que estamos sobrescrevendo
    public String toString() {             // minúsculo, como em Object
        return name + ", $ " + price + ", " + quantity
             + " units, Total: $ " + totalValueInStock();
    }
}

12 Checklist antes de commitar

  • Nome da classe UpperCamelCase e o arquivo tem o mesmo nome da classe pública?
  • Todo método começa com letra minúscula?
  • toString / equals / hashCode estão em minúsculas e anotados com @Override?
  • Constantes static final estão em UPPER_SNAKE_CASE?
  • Variáveis em lowerCamelCase, sem _, sem $, sem acentos?
  • Nenhum nome de 1–2 letras sobrevivendo fora de laços e coordenadas?
  • Faltou algum get / set / is nos acessores?
  • Dá para dizer o que a variável guarda só lendo o nome, sem olhar o tipo?
  • Existe algum data, info, temp, manager ou value2 no código?
  • Os nomes continuam verdadeiros depois da última mudança de comportamento?
